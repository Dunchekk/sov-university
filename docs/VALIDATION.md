# Проверка реализации

Дата: 11.11.2026. Среда: macOS ARM64, отдельный Colima `hackathon` (4 CPU / 6 GiB), локальный PostgreSQL. E2E используют отдельную БД `ryadom_test` и отдельный storage. Контейнерная приёмка выполнялась на новых volumes проекта `ryadom-smoke`: PostgreSQL 17.11, Node 22.23.4.

## Фактически выполнено

- TypeScript strict, ESLint и production build прошли. Проверены стандартная сборка на хосте, standalone-сборка приёмки и Docker-образ. Next 16.4.6 / React 19.3.1 / Prisma 7.10.1 закреплены lockfile.
- Vitest: **14 проверок прошли** — посещаемость, оценка, обязательные работы, раскладка календаря, мгновенное событие в полночь, ограничение входного потока, стандартные ICS и ресурсные лимиты.
- Playwright: **22 E2E/API-сценария прошли за 1,3 минуты** вместе с подготовкой свежего standalone-сервера. Из них 20 в Chromium, по одному составному сценарию в Firefox и WebKit. Версии из установленного Playwright: Chromium 158.0.8127.18, Firefox 159.0, WebKit 27.2. Safari как отдельное приложение не запускался.
- Проверены 16 основных маршрутов × 2 темы × 3 ширины: 1440, 1280 и 360 px. Переполнения страницы, `pageerror` и ошибок browser console в этом прогоне нет. 12 снимков главной, календаря и услуг в двух темах для desktop/mobile сохранены в `screenshots/`; ключевые снимки просмотрены визуально.
- Межбраузерный сценарий: будущий день с главной → календарь → дисциплина → поиск среди 26 участников → другой семестр учебного плана → предзаполненное финансовое обращение второго студента → мобильное меню и личное событие → Escape и возврат фокуса. После устранения различия «ср»/«Ср» ошибок гидрации WebKit нет. Отдельно проверены страницы на dev-сервере Webpack после компиляции.
- Docker: чистые migrate/seed и вход; процесс UID 1000; создание заявки и загрузка PDF; ICS worker, включая мгновенное событие; анонимная подписка и отзыв; рестарт app + db; сохранение сессии, заявки и совпадение SHA-256 скачанного файла. После окончательных исправлений образ пересобран и smoke повторён успешно.
- Сетевые запросы окончательного Docker-образа проверены на главной, месяце календаря, участниках курса и интеграциях. Внешних запросов нет; загружены 6 локальных WOFF2 Inter (Latin/Cyrillic, 400/500/600); ошибок и предупреждений консоли нет.
- Backup/restore: скрипт создал согласованные `pg_dump` и архив файлов, вернул приложение в рабочее состояние. Восстановление выполнено в **отдельную новую БД и volume**. Проверены 10 восстановленных обращений и совпадение SHA-256 загруженного PDF. Проверочные копии удалены; исходный стенд сохранён.
- Caddy 2.11.9: `caddy validate` подтвердил конфигурацию, Compose production-конфигурация валидна. Форматирование Caddyfile исправлено. Публичный сертификат не запрашивался.
- Демонстрационный PDF отрисован Poppler и проверен визуально; кириллица читается, статический Inter встроен в файл. Лицензия OFL включена.
- Выполнено ровно **6 независимых ревью Astra High**. Подтверждённые дефекты исправлены; существенные случаи покрыты регрессиями. Журнал: `REVIEWS.md`.
- `npm audit`: 0 уязвимостей после обновления транзитивного minimatch. Поиск в зависимостях, исходниках и runtime не обнаружил Depot, внутренних пакетов или внутренних CDN. `.env`, `.local`, storage и тестовые отчёты исключены из Git и Docker context.

Локальные диагностические файлы: `.local/e2e-final.log`, `.local/docker-final-build.log`, `.local/docker-final-smoke.log`, `.local/docker-smoke-result.json`, `.local/restore-result.json`. Они не входят в Git; этот документ сохраняет результаты без cookie, паролей, исходных файлов импорта и секретных URL.

| 1280 px |   94 мс |        55–843 мс |                         418 / 364 мс |

Исходные замеры — `.local/ui-metrics-*.json` и `.local/roster-metrics-*.json`. Месяц наполнен seed-занятиями, сроками и событиями; отдельный нагрузочный benchmark не заявляется.

## Реальные ограничения

- Внешние Google/Apple/Outlook аккаунты и публичный HTTPS не подключались. Локальный feed и формат протестированы; доступность URL и частота внешнего обновления проверяются после публикации и зависят от провайдера.
- Яндекс в актуальной официальной справке описывает импорт по ссылке как снимок. UI и README отражают это вместо обещания неподтверждённой подписки.
- ICS RDATE/EXRULE/RANGE и неизвестные TZID/нестандартные VTIMEZONE пропускаются с явным предупреждением. Известные IANA, UTC, floating time, RRULE, EXDATE, RECURRENCE-ID поддерживаются. Лимиты и срок preview показаны пользователю.
- Интерфейс сотрудника и реальные интеграции университета не входят в v1: отправленные обращения, отчёты и достижения остаются на рассмотрении; завершённые примеры есть в seed. Праздники в ориентировочном сроке услуги не учитываются.
- `pg` 8 выводит предупреждение о будущем изменении concurrent query API в `pg` 9; ошибок транзакций не наблюдалось. Major 9 не подключён. ESLint 9.39.5 выбран по совместимым peer-диапазонам Next-плагинов; npm предупреждает об окончании поддержки этой ветки dev-инструмента.
- Публикация в GitHub, публичный deploy, отправка на конкурс и действия с реальными внешними данными не выполнялись.

## Замеры после оптимизации кабинета

21.11.2026. Исходный снимок `6606fbb` и оптимизированную сборку сравнили на одном Mac с Node.js 22.23.3 и отдельным PostgreSQL 17.11. В базе было 3 002 синтетических студента, 54 032 записи на дисциплины, 117 065 результатов и 216 120 отметок посещаемости. Обе сборки запущены в режиме production standalone. Время в браузере измерено от события клика в боковом меню до кадра с готовым содержимым.

| --- | ---: | ---: |
| Дисциплины | 346 → 78 мс | 347 → 47 мс |
| Оценки и посещаемость | 98 → 64 мс | 80 → 48 мс |

При последовательном обходе разделов календарь отправлял 7 фоновых запросов расписаний до оптимизации и 0 после. Начальный JS маршрута календаря сократился с 583 до 568 КиБ до сжатия по отчёту Next.js.

Для студента с 18 дисциплинами число операций Prisma в `myCourses` сократилось с 73 до 4. Это число вызовов ORM по реализации, включая загрузку записей на дисциплины. Prisma может выполнять дополнительные SQL-запросы для связей.

Нагрузка распределялась между главной и пятью маршрутами из таблицы. Тест чтения использовал две авторизованные демосессии. Синтетические записи задавали объём таблиц. Одновременный вход тысяч пользователей и пропускную способность будущей инфраструктуры нужно проверять отдельно.

В отдельном тесте холодного dev на том же исходном коде переход на Turbopack сократил первый ответ `/login` с 2,90 до 0,94 с, главной с 2,87 до 1,17 с, «Дисциплин» с 697 до 441 мс. Повторный ответ «Дисциплин» занял 152 и 148 мс соответственно.

Штатная production-сборка, TypeScript, ESLint, 14 unit-тестов и 46 E2E-сценариев проверены. В общем прогоне прошли 45 E2E в Chromium, Firefox и WebKit. Новый сценарий навигации прошёл отдельно после исправления перехвата отменённого запроса в тесте. Fast Refresh проверен в Chromium изменением текста клиентского компонента во временной копии проекта.

Для повтора соберите standalone с тестовым окружением через `npm run test:e2e`. На отдельной локальной базе `ryadom_test` с ролью `ryadom_perf` и демоданными запустите `node scripts/seed-performance.mjs 3000`. Команда `node scripts/measure-performance.mjs` запускает готовую сборку на порту 3002, выводит JSON замеров и завершает сервер. Первый аргумент может указывать на каталог другой готовой сборки с её `.env.test` и синтетическими учётными данными.
