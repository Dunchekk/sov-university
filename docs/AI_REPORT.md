# Разработка с ИИ

Разработан конкурсный прототип «Рядом» по пользовательской спецификации v1.0. Основной агент работал в локальном репозитории с тематическими Git-ветками, сам выбирал обычные технические решения и не публиковал проект. Внешние университетские сервисы, реальные студенты и персональные данные не использовались.

## Инструменты и задачи

- Codex: анализ спецификации, план, реализация frontend/backend/БД, сценарии проверки, эксплуатационная документация.
- Независимый read-only architecture_researcher на Astra High: шесть запланированных проверок архитектуры, доступа, учебной математики, личных операций, ICS и финальной приёмки. Главный агент оценивал находки и сам менял код. Журнал — `REVIEWS.md`.
- Shell/Node/npm, Prisma/PostgreSQL, Colima/Docker CLI, Playwright с Chromium/Firefox/WebKit, Vitest, ESLint, TypeScript; Git только локально.
- Официальные документации Next.js из установленного пакета, Better Auth/Prisma и библиотек iCalendar; официальные инструкции календарных провайдеров. Навигация чужих аккаунтов не применялась.
- Локальные workflows Sites (только подготовка репозитория, без регистрации/хостинга) и PDF (создание/визуальная проверка демонстрационных PDF). PDF отрисованы Poppler; шрифты и скриншоты проверены визуально.

## Ключевые рабочие постановки

1. Превратить спецификацию в план этапов и проверяемые границы данных, не ограничиваться статичным макетом.
2. Проверить доступ двумя студентами: общий курс и публичное расписание не должны открывать приватные результаты/файлы.
3. Использовать единый расчёт оценок и посещаемости и объяснить пользователю условия допуска.
4. Проверить отправку формы при двойном клике, гонке версий и потерянном ответе сервера.
5. Проверить ICS на DST, date-only, RRULE, EXDATE, переносе RECURRENCE-ID и отзыве токена до условного GET.
6. Проверить реальный Compose-запуск, рестарт, две темы и доступность основных действий на360px.

Это краткое изложение задач, а не копия приватной переписки или учётных данных.

## Исправления по наблюдениям

Ревью выявили nullable CHECK в PostgreSQL, чтение слишком большого тела до проверки, отображение удалённых личных событий, некорректную обработку неучтённой посещаемости, гонку удаления черновика, несовпадение предпросмотра и сохранённого snapshot, потерю неотправленных файлов, повтор submit после сетевого сбоя, экспорт причины пересдачи и нормализацию ошибочной all-day даты библиотекой. Исправления внесены главным агентом, для существенных случаев добавлены регрессии.

Браузерный тест обнаружил гонку reload сразу после сохранения: URL черновика теперь меняется синхронно. Визуальная проверка PDF обнаружила недостающие кириллические символы при subset variable font: используется статический Inter без subset. При нестабильном Fast Refresh очищался только сгенерированный кеш; dev переведён на Webpack, приёмка выполняется на новой production standalone-сборке.

Кроссбраузерная проверка выявила различие регистра русских дней недели между Node и WebKit («ср»/«Ср»), вызывавшее ошибку гидрации. Форматирование унифицировано. Поиск участников недоступен до подключения React, чтобы ранний ввод не терялся; перед открытием основных диалогов явно устанавливается фокус на кнопку для корректного возврата в WebKit. Тест проходит по ссылкам интерфейса, не прерывая фоновую загрузку Next.js принудительными перезагрузками.

## Границы и результат

Рабочие действия сохраняются в PostgreSQL и приватном storage. Сотрудническая обработка, реальные платежи, SSO, OAuth и двусторонние календарные интеграции исключены спецификацией. Изменившаяся документация Яндекса отражена честно: импорт по ссылке не назван обновляемой подпиской. Публичный HTTPS и реальные аккаунты провайдеров не использовались. Фактически выполненные проверки и оставшиеся ограничения зафиксированы в `VALIDATION.md`.
