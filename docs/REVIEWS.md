# Независимые ревью

## №1 — архитектура (Astra High)

Read-only проверка PLAN и SPEC. Приняты все четыре уточнения:
- Idempotency unique = student+operation+key; hash хранится отдельно. Конкурентные повторы сериализуются транзакцией.
- Стабильные lesson IDs и sequence заложены до первой миграции. Import identity = source+UID+исходный recurrence key, single sentinel для одиночного события.
- ical.js требует регистрации timezone: встроенные VTIMEZONE + локальный набор IANA; неизвестные зоны не угадывать. Ограничить не только результаты, но и итерации.
- Enrollment/Attendance/Result используют составные связи с courseId; файлы проверяют owner+purpose+родителя+состояние.

Код ещё не проверялся. Следующее ревью после основания.

## №2 — основание и доступ (Astra High)

Найдены и исправлены два P2:
- Ограничения JSON/login проверялись после полного чтения: выделен потоковый reader, который отменяет чтение при превышении; Better Auth получает ограниченное тело.
- PostgreSQL CHECK допускает NULL: отдельная миграция делает оба варианта события строго двухсторонними (начало и конец обязательны).

Allowlist, Origin, session, owner/purpose, idempotency и составные FK: обходов не найдено. Проверки: typecheck/lint; живой API входа двух пользователей, приватный DTO, чужой файл404, signup404, Origin403, отзыв сессии.

## №3 — учебный сценарий (Astra High)

Исправлены четыре подтверждённых дефекта:
- Обычный календарь исключает удалённые личные события; tombstone доступен только внутреннему режиму экспорта.
- Раскладка учитывает минимальную визуальную высоту; подпись конфликта использует реальные интервалы.
- Достижимость зачёта учитывает просроченные обязательные работы, а UI объясняет конкретную причину.
- Журнал строится от завершённых занятий: отсутствие отметки становится UNRECORDED, не пропуском.

Проверки добавлены для расчётов и визуальных пересечений. Утечек через сравнение в проверенных выборках не найдено.
