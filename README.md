# Рядом — студенческий кабинет

Полная локальная версия конкурсного прототипа: Next.js, серверные сессии, PostgreSQL, личные действия, приватные PDF, импорт/экспорт и подписка ICS. Университет «Северный», люди, учебные и финансовые сведения вымышлены. Отправки во внешние университетские системы нет.

На машине разработки уже запущен отдельный стенд: **[http://localhost:3010](http://localhost:3010)**. Доступы двух студентов — `.local/docker-smoke-credentials.json` (файл0600, исключён из Git). Его команды управления: `docker --context colima-hackathon compose -p ryadom-smoke --env-file .env.smoke ps`, `stop` или `up -d`. Следующая инструкция предназначена для самостоятельного запуска нового окружения.

## Быстрый запуск в Docker

Нужен Docker Engine/Compose v2.24+ или Colima на Mac. Docker Desktop не требуется и не устанавливался. Все команды выполняются из корня проекта.

```sh
# На этой машине создан отдельный профиль, существующие contexts не изменялись.
colima start hackathon --cpu 4 --memory 6 --disk 30 --activate=false --ssh-config=false
export DOCKER_CONTEXT=colima-hackathon

node scripts/init-env.mjs
docker compose up -d --build
docker compose --profile demo up --build seed
mkdir -p .local
docker compose cp seed:/app/.local/demo-credentials.json .local/docker-credentials.json
chmod 600 .local/docker-credentials.json
```

Открыть [http://localhost:3000](http://localhost:3000). Два аккаунта записаны в `.local/docker-credentials.json`; пароли не выводятся в обычные логи. A — Александра Миронова, дизайн, бюджет; B — Михаил Соколов, программная инженерия, договор. Для Linux убрать `DOCKER_CONTEXT` и шаг Colima.

`init-env` создаёт случайные секреты с правами0600 и **не перезаписывает** существующий файл. Docker передаёт внутренний `DATABASE_URL`, поэтому порт PostgreSQL наружу по умолчанию закрыт. `app` запускается после успешных миграций, работает от `node` (UID1000), имеет healthcheck и отдельный volume файлов. Образ инструментов содержит Prisma CLI/seed; runtime содержит standalone-сборку без dev-инструментов. Образы закреплены: Node22.23.4, PostgreSQL17.11, Caddy2.11.9.

```sh
docker compose ps
docker compose logs --tail=40 app migrate
docker compose restart app db     # данные и сессии сохраняются
docker compose stop              # остановка без удаления volumes
```

Не используйте `down -v`, если нужно сохранить данные. На этой машине основной dev PostgreSQL находится в проекте `ryadom`, а чистая контейнерная приёмка — в отдельном `ryadom-smoke` на порту3010.

## Разработка на хосте

Node22 LTS, рекомендуется22.23.4. На данной машине Node22 доступен в `/opt/homebrew/opt/node@22/bin`; глобальный Node26 не входит в проверенный диапазон.

```sh
export PATH=/opt/homebrew/opt/node@22/bin:$PATH
export DOCKER_CONTEXT=colima-hackathon
node scripts/init-env.mjs
npm ci
docker compose -f compose.yaml -f compose.dev.yaml up -d db
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Dev подключается к `127.0.0.1:5438`, хранит файлы в `.data/files`, доступы — `.local/demo-credentials.json`. Полный Compose использует собственный volume файлов: не смешивайте способы seed и хранения. `.env`, `.local`, `.data`, test reports и генерируемый Prisma Client исключены из Git и Docker context.

Для production-сборки на хосте: `npm run build`, затем `npm start`. Docker использует standalone `server.js`. Dev использует поддержанный Webpack для стабильного HMR; production собирается Turbopack. Не запускайте два `next dev` в одном дереве с разными distDir одновременно: их генерируемые типы могут мешать Fast Refresh. После переименования модулей, отличавшихся регистром, при stale HMR удаляется только соответствующая сгенерированная `.next*` директория, не БД и не storage.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
node scripts/setup-test.mjs
npx playwright install chromium firefox webkit
npm run test:e2e
```

E2E собирают и запускают production standalone и работают с настоящим API и отдельной БД `ryadom_test`, собственным storage и портом3001. Прямые DB-fixtures отказываются работать вне этой БД. Проверяются два аккаунта, запреты доступа, формы и idempotency, гонки/обрывы ответа, PDF, календарь, ICS и отзыв feed, темы и ширины1440/1280/360. Тесты последовательные, создают собственные рабочие записи; seed сохраняет изменения между запусками. Счётчики throttling очищаются только как fixture отдельного auth-теста. Traces/video отключены, чтобы не сохранять пароли/cookie/feed tokens; остаются текстовые ошибки и безопасные скриншоты страниц.

Фактическая приёмка: [VALIDATION.md](docs/VALIDATION.md). Сопоставление с ТЗ: [REQUIREMENTS.md](docs/REQUIREMENTS.md). Независимые ревью: [REVIEWS.md](docs/REVIEWS.md). Скриншоты — `docs/screenshots/`; метрики локального прогона — `.local/ui-metrics-*.json`.

Основной набор выполняется в Chromium; общий пользовательский сценарий дополнительно запускается в Firefox и WebKit. `npm run test:browsers` запускает только эти два дополнительных браузера. Занятый порт3001 считается ошибкой: тесты не переиспользуют случайную старую сборку.

## Архитектура и правила данных

App Router Server Components загружают страницы через серверные сервисы, без HTTP-запросов к собственному API. Клиентские компоненты отвечают за формы, диалоги, поиск и календарную навигацию. `src/modules` содержит домены, `src/server` — сессии/доступ/транзакции/ошибки, `src/shared` — токены, типографику, компоненты и функции времени. CSS Modules, локальный Inter, чёрная тёмная тема; сторонней UI-библиотеки и Depot нет.

PostgreSQL — источник прикладных данных. Prisma7 + pg adapter, миграции и составные FK ограничивают связи курса/enrollment/результатов. Оценка и посещаемость вычисляются одним доменным сервисом: `null` отличается от0; будущие/отменённые занятия исключены; отсутствие отметки — «не учтено»; штраф применяется один раз; официальный итог показывается отдельно от прогноза. Сроки услуг — рабочие дни без выходных; праздничный производственный календарь в v1 не подключён, срок обозначен ориентировочным.

Better Auth хранит сессии в БД, Argon2id64MiB/3/1 хеширует пароль, публичная регистрация закрыта. Внешний auth endpoint разрешает только вход/выход/проверку сессии. Origin проверяется всеми мутациями. Приватные сущности выбираются через текущего студента; общий курс не открывает чужие результаты. Подробности профиля отсутствуют в исходном публичном DTO. ID не служит разрешением доступа.

Черновики имеют version, отправки — idempotency key с отдельным payload hash. PostgreSQL advisory locks сериализуют конкурентные повторы. Переход статуса, история, комментарий и уведомление записываются транзакционно. Студент не может присвоить сотруднический статус. Без интерфейса сотрудника последующая проверка остаётся ожидаемой: seed содержит завершённые и требующие уточнения примеры.

PDF до10MiB, квота50MiB, owner/purpose/parent/state проверки, случайный storage key вне `public`, скачивание как attachment. Неотправленные файлы восстанавливаются после reload и удаляются владельцем; отправленные версии неизменяемы. Истёкший готовый документ возвращает410. Демонстрационные PDF явно маркированы; юридической силы не имеют.

## Календарные интеграции

Импорт — снимок из файла, без URL-fetch, OAuth и двусторонней записи. `ical.js` проверяет компоненты и генерирует экспорт, `node-ical` обрабатывает IANA/Intl, RRULE, EXDATE и RECURRENCE-ID. Разбор выполняется worker thread с heap96MiB и deadline8s. Ограничения:5MiB/2000 исходных VEVENT/10000 вхождений/366дней. Превышение отменяет весь импорт; уменьшите диапазон. Неподдержанные RDATE/EXRULE/RANGE и неизвестные TZID (включая нестандартные VTIMEZONE) явно перечисляются в предупреждениях; соответствующие серии пропускаются. HTML остаётся текстом, вложения и напоминания не выполняются.

Для floating time выбирается зона, по умолчанию Europe/Moscow. Timed-инстанты хранятся в UTC, all-day — отдельными датами с эксклюзивным концом. Импортные мгновенные события разрешены стандартом; личный редактор требует положительную длительность. Идентичность: источник+UID+исходный RECURRENCE-ID. Перенос сохраняет ID; повтор файла обновляет совпадения. Исчезновение из файла не удаляет старые события. «Заменить весь слой» отдельно подтверждается и отменяет все отсутствующие события, включая события вне выбранного окна.

Preview принадлежит пользователю и действует15минут. Commit повторно разбирает сохранённый исходник, не принимает клиентский список событий; повтор подтверждения идемпотентен. Исходник стирается сразу после commit; истёкший недоступен немедленно и стирается при следующем запуске/импорте либо в течение5минут работающим housekeeping. Хранятся до3 активных preview и до10 слоёв.

Экспорт использует стабильные UID/SEQUENCE/LAST-MODIFIED, CRLF/escaping/UTF-8 folding. По умолчанию — пары, экзамены и учебные сроки. Личное выбирается явно; финансовые сроки отдельным флажком, без сумм. Оценки, причины пересдачи, посещаемость, участники и личные сведения не экспортируются.

Feed —32 случайных байта, в БД только SHA-256; URL показывается один раз. До10 активных ссылок, отзыв проверяется до ETag/304. Окно:30дней назад и180вперёд; отменённые записи сохраняются. Ответ `private,no-store`, без общего/CDN cache. Токены исключены из Next dev logging и HTTP-логов Caddy, Referrer-Policy=no-referrer. Для внешнего провайдера требуется публичный HTTPS: localhost пригоден для файлов и локальной проверки feed, но недоступен Google/Outlook.

Инструкции проверены11.11.2026 по официальным источникам: [Google импорт](https://support.google.com/calendar/answer/37118?hl=ru), [Google URL](https://support.google.com/calendar/answer/37100?hl=ru), [Apple](https://support.apple.com/ru-ru/102301), [Outlook](https://support.microsoft.com/en-us/outlook/import-or-subscribe-to-a-calendar-in-outlook-com-or-outlook-on-the-web). Частоту обновлений определяет провайдер. **Яндекс:** [текущая справка](https://yandex.ru/support/yandex-360/customers/calendar/app/ru/import) описывает оба вида импорта, включая «По ссылке», как разовую копию. Поэтому интерфейс не обещает неподтверждённую обновляемую ICS-подписку Яндекса; предлагает повторный импорт или подписку в других поддерживающих её календарях.

## Seed и восстановление доступа

Seed идемпотентен: фиксированные IDs/upsert и маркеры версии, повторный запуск не стирает действия пользователя. `DEMO_BASE_DATE=YYYY-MM-DD` задаёт опорную дату **первого** заполнения; иначе используется текущая дата Москвы. Изменение переменной не перематывает уже существующие данные. Для нового стенда используйте новое имя Compose-проекта и новые volumes. Не сбрасывайте чужую БД.

Если локальный файл доступов потерян, явная административная команда `npx tsx scripts/reset-demo-passwords.ts` создаёт новые пароли только двух seed-аккаунтов и отзывает их сессии. В Docker: `docker compose --profile demo run --rm seed npx tsx scripts/reset-demo-passwords.ts`, затем снова скопировать файл из volume через seed-контейнер. Эта операция не доступна по HTTP.
